# Развитие SharoBoy — ройдмап

> Общий план направлений развития игры. Записан, чтобы не перебирать варианты
> заново при обнулении контекста в будущих сессиях. Каждый пункт — направление
> для отдельного обсуждения и детализации.

## Текущее состояние (опорные точки)

- Стек: React 18 + TypeScript + Vite + TailwindCSS 4, тесты vitest.
- Уже есть: система уровней (`levelBuilder`), достижения (`achievements`),
  прокачка/апгрейды (`upgrades`), разные классы экрана (mobile/fhd/4k),
  мировой топ через Supabase с фильтром по категориям, проверка ника/профanity,
  ежедневные лимиты через Edge Function «scores».
- Раздел `src/game/`: `achievements`, `effects`, `leaderboard`, `levelBuilder`,
  `profanity`, `render`, `viewport`, `frame.invariant`.
- Есть тесты ко всем ключевым модулям (`*.test.ts`).
- CI: `deploy.yml` (Pages) + `supabase.yml` (функции/миграции).

## Направления развития

### 1. Лор и сеттинг

Ракетка — это не персонаж, а **инструмент** или **элемент воображения**. Нужно
продумать небольшой лор, почему именно ракетка и какой путь ведёт к цели.

Идеи для обсуждения:

- Ракетка как инструмент управления энергией/мячом в руках невидимого игрока.
- Путь от начала до финального босса как путешествие через зоны с нарастающей
  сложностью, где каждый уровень — испытание на мастерство.
- Боссы — хранители зон, которых нужно победить, чтобы продвинуться.
- Кристаллы — энергия, которую игрок собирает на пути; валюта прогрессии.

_Статус: требует обсуждения и финализации._

---

### 2. Боссы

Фазовые бои с уникальными механиками поверх существующей системы уровней.

**Фазы боссов:**

- Босс меняет паттерн поведения при потере здоровья (2-3 фазы).
- С каждой фазой — новые атаки, ускорение, новые типы снарядов.

**Критический удар x3:**

- Если игрок попадает по боссу 3 раза подряд **без касания ракеткой** (мяч отскочил от стен/других объектов и всё равно попал) — активируется критический урон x3.
- Счётчик сбрасывается, если ракетка коснулась мяча между попаданиями по боссу.

**Разнообразие боссов:**

- **Босс 1** — фазовый базовый (знакомство с механикой фаз).
- **Босс 2 «Осьминог»:**
  - Центральное тело + движущиеся щупальца.
  - Основной урон по телу **заблокирован**, пока живы щупальца — нужно сначала уничтожить все щупальца.
  - Щупальца двигаются и перекрывают тело, создавая динамичную защиту.
  - Периодически бросает **бомбы** — при попадании в ракетку отнимают одну жизнь.
- **Финальный босс** — очень сложный, несколько фаз, комбинация механик предыдущих боссов.

### 3. Механика ракетки и физика ядра

**Вращение ракетки:**

- Левая кнопка мыши — поворот против часовой стрелки.
- Правая кнопка мыши — поворот по часовой стрелки.
- Вращение позволяет **ударить с силой** по мячу, придавая ему временное
  ускорение с возможным усиленным эффектом.
- Связь с увеличенной гравитацией: простое отбитие не позволяет достигать
  верхних блоков — нужно использовать силу вращения. Без удара сила
  воздействия на верхние блоки может составлять ~50% от обычной.

**Энергетическая система блоков:**

- Блоки имеют энергию в виде **рамки вокруг них**.
- Сила удара мяча прокачивается через различные улучшения.
- По мере уменьшения энергии блока — **градиент на шарах** вместо значков внутри
  них (визуальная индикация оставшейся энергии).

**Гравитация:**

- Увеличенная гравитация как модификатор уровня/модификатор режима — мяч сильнее
  тянет вниз, требуется активное использование силы удара.

### 4. Кампания и уровни (roguelike-структура)

**Система путей:**

- Кампания — маршрут от старта до финального босса с ветвлениями.
- Ветвления **не повторяются** в рамках одного забега — каждый проход уникален.
- На развилках игрок выбирает направление (риск vs награда).

**Типы локаций на пути:**

- **Обычные уровни** — стандарная механика разбиения блоков.
- **Мини-боссы** — упрощённые версии основных боссов, дают ощутимую награду.
- **Случайные события** — неожиданные ситуации с выбором (риск/награда).
- **Магазины** — уникальные улучшения за валюту, заработанную в забеге.
- **Квестовые задания / челленджи** — выполнить условие за уровень для бонуса (например, прожить 15 секунд без потери мяча, разбить все блоки без промаха).
- **Секретные уровни** — скрытые комнаты с особыми наградами.

**Валюта забега:**

- Внутриигровая валюта (монеты/кристаллы), зарабатываемая в уровнях.
- Тратится в магазинах на уникальные улучшения, недоступные в основной прокачке.
- Сгорает в конце забега (roguelike-элемент).

### 5. Перки и усиления

**Оффенсивные перки:**

- **Проникающий мяч** — пролетает сквозь N блоков.
- **Взрывной мяч** — при разрушении блока взрывает блоки вокруг себя
  (особенно эффективно с магнитной ракеткой).
- **Раздвоение мяч** — каждые 10 попаданий мяч дублируется (до 3 штук).
- **Теневой мяч** — второй полупрозрачный мяч летит с задержкой в 1 сек,
  догоняя основной.
- **Автонаведение** — перк или временный эффект, мяч автоматически наводится на
  ближайшие блоки.

**Утилитарные перки:**

- **Расположение мяча** — возможность расположить мяч на ракетке перед стартом
  с появляющимся лучом направления движения при пуске.
- **Хрупкие блоки** — перк, преобразующий несколько блоки, к которым прикоснётся
  мяч, в хрупкие (разбиваются с одного касания). Отдельный стиль с трещинами для
  визуального отличия.
- **Магнитная ракетка** — притягивает мяч вблизи для целенаправленного пуска
  (с кулдауном притяжения).

**Модификаторы режимов (твины core-механики):**

- **Инверсия управления** — управление ракеткой инвертировано.
- **Одна жизнь** — permadeath на забег, но утроенная награда.
- **Постоянное ускорение** — мяч постоянно набирает скорость, нет потолка.
- **Зеркало** — отражение всего игрового поля.

**Комбинации эффектов (синергии):**

- Проникающий мяч + магнитная ракетка — контролируемое пробивание рядов.
- Взрывной мяч + хрупкие блоки — цепные реакции разрушения.
- Автонаведение + увеличенная гравитация — компенсация физики.
- _Требует отдельной проработки полного дерева синергий._

### 6. Типы блоков

> ✅ **Реализовано (beta, 2026-09-23):** все шесть типов — `blockKinds.ts` (данные),
> `game/blockMotion.ts` (маршрутизатор траекторий), `physics/special.ts` (эффекты
> удара), `game/blockSpawn.ts` (расстановка по уровню с 3-го), рендер —
> `render/blockKinds.ts`. С 4-го уровня — парные порталы с кулдауном пары.

**Реагирующие на попадание (эффекты удара):**

- **Энергетические** — с рамкой энергии, градиент по мере уменьшения здоровья.
- **Хрупкие** — разбиваются с одного касания (стиль с трещинами). Могут
  активироваться перком.
- **Пружинный** — при ударе **ускоряет мяч на время**; отскок с выраженной
  пружинной анимацией (сжатие-расжатие блока, «выстреливающий» отскок).
  Реиграбельно с существующей системой скорости (`physics/speed.ts`).
- **Ватный** — при ударе **замедляет мяч на время**; мягкая «вязкая» анимация
  отскока, приглушённый звук. Парная к пружинному тактика выбора маршрута.

**Реагирующие на попадание (геометрия):**

- **Крутящийся** — продолговатый (овал/капсула), раскручивается от удара в одну
  из половин: сторона попадания задаёт направление и силу вращения; угловая
  скорость меняет нормаль отскока у следующих ударов (вращающееся «весло»).
  Постепенно гаснет трением.

**Движущиеся (пассивные траектории):**

- **Пульсирующий** — плавно циклично меняет размер (масштаб rx/ry по синусоиде);
  хитбокс обновляется каждый кадр — окно для ловкого прохода.
- **Дрейфующий** — движется по заданной траектории в пределах: горизонтально,
  вертикально или **по окружности** (радиус/фаза/скорость индивидуальны).
  Расширение уже существующих дрейфов блоков (`swayAmp`, `bobAmp` в
  `game/updateStep.ts`) до общего «маршрутизатора» траекторий.

**Пространственные (пары):**

- **Телепортирующий (чёрная дыра)** — парный блок: при попадании мяч мгновенно
  перебрасывается в парный блок **с сохранением траектории** (вектор скорости).
  Визуал: чёрная дыра с аккреционным кольцом, звук «воронки». Кулдаун пары после
  прыжка против зацикливания; шар у спавна парного блока на мгновение
  неуязвим для повторного телепорта.

- _Технически: все новые типы — расширение спецификаций блоков (`types.ts`,
  `levelBuilder`, `levelPatterns`) + чистые модули поведения в `src/game/game/`
  и `src/game/physics/`; рендер — в `src/game/render/blocks.ts`._

### 7. Прогрессия и метагейм

**Прокачка между забегами (roguelite-элемент):**

- Постоянный прогресс, который сохраняется между забегами.
- Валюта/опыт, зарабатываемая в кампании, тратится на постоянные улучшения.
- Отдельно — временные улучшения внутри забега (см. раздел «Магазины»).

**Достижения с наградами:**

- Привязать достижения к конкретным игровым событиям (первый босс, x10 критов и т.д.).
- Награды — разблокировка контента или бонусная валюта.

**Ежедневные испытания:**

- Фиксированный сид — одинаковая последовательность уровней для всех в течение дня.
- Отдельная таблица лидеров на день.

### 8. Система жизней и валюты

**Жизни (шары):**

- При начале матча шары **не появляются вновь** — их количество переходит от
  уровня к уровню.
- Добыча жизней на пути:
  - Убийство боссов.
  - Выполнение челленджей.
  - Особые магазинчики на пути за кристаллы.

**Кристаллы (валюта забега):**

- За особие заслуги: выполнение челленджей, победа над боссами, секретные
  уровни, продажа ненужных перков.
- Тратятся в магазинах на уникальные улучшения и жизни.
- Сгорает в конце забега (roguelike-элемент).

### 9. Метрики и подсчёт очков

Необходимо сделать прозрачным образование итоговых очков, зависящих от:

- Количество разрушенных блоков (с учётом типа блока).
- Использованные модификаторы сложности (чем сложнее — тем больше очков).
- Оставшиеся жизни (бонус за каждую незатраченную жизнь).
- Время прохождения (бонус за скорость).
- Синергии и комбо (критические удары, цепные разрушения).
- Прогрессия по кампании (множитель за глубину прохождения).

Отображение: детальная разбивка по окончании забега, чтобы игрок понимал, за что
получил очков.

### 13. Пользовательские карты и модификации

**Редактор карт:**

- Визуальный редактор на существующих спецификациях уровней
  (`levels`/`levelBuilder`): расстановка блоков всех типов, выбор фона,
  просмотр и тестовый прогон без выхода из редактора.
- Экспорт/импорт карты кодом или ссылкой (детерминированный формат,
  совместимый с сидами и паттернами).

**Публикация и модерация:**

- Каталог пользовательских карт (Supabase: таблицы карт, авторы, оценки).
  Важно: с 30.10.2025 Supabase не выдаёт Data API-доступ новым таблицам
  автоматически — каждая новая таблица получает явные `grant`
  (anon/authenticated/service_role) в той же миграции, что и `create table`
  (см. `supabase/migrations/20250101000007_grants_api_access.sql`).
- **Модерация администратором (первый этап — вручную)**: очередь на публикацию,
  одобрение/отклонение, бан карт и авторов, жалобы.
- Локальный плейлист «мои карты» и «одобренные сообществом».

**Мод-модель:**

- Общая модель модификаций: карта + набор опциональных правил (модификаторы
  режима из раздела «Перки»: гравитация, инверсия, зеркало и т.д.).
- Целевая архитектура: декларативные мод-манифесты (JSON) поверх чистых
  модулей `src/game/` — без произвольного кода в пользовательском контенте
  (безопасность: sandbox по схеме, никаких `eval`).
- Оценки, теги сложности, совместимость с достижениями (в мод-картах
  достижения/лидерборды — отдельно или выключены).

**Решение (24.09.2026): делать поэтапно, этап A — следующим большим этапом.**

- **Этап A — «код карты», локально (без сервера):**
  - сериализуемый детерминированный формат поверх существующих спецификаций
    (`levels`/`PatternSpec`); спецблоки §6 подключаются тем же сид-декоратором
    (`decorateBlocks`) — формат описывает раскладку, а не каждый спецблок;
  - импорт/экспорт картой-кодом (строка), плейлист «мои карты» в localStorage;
  - просмотр/тестовый прогон карты без выхода из меню (переиспользует
    `buildFromSpec` — физику и рендер трогать не нужно).
  - Оценка: средний объём, низкий риск; опирается целиком на готовое ядро.
- **Этап B — каталог и модерация (после плейтеста этапа A):**
  - таблица `maps` + Edge Function `maps` по образцу `scores`: anon JWT,
    подпись автора вместо секретной — модерация флагом `approved` вручную;
  - без прямого доступа клиентов к БД; достижения и мировой топ для
    мод-карт — выключены до отдельного решения;
  - JSON-мод-манифесты (без `eval`) — только после этапа B, не блокер.
- **Не делать:** серверную валидацию карт и автоматическую модерацию (объём не
  оправдан на текущей аудитории); полноэкранный визуальный редактор — сначала
  код-формат и текстовый импорт, редактор — по спросу.

_Статус: целесообразность подтверждена, план поэтапный (см. выше и
memory-bank/activeContext.md)._

### 14. Кооперативный режим и онлайн

**Варианты кооператива (требует выбора архитектуры):**

- **Разделённое поле** — экран делится пополам, каждый игрок держит свою
  половину блоков; проигрыш половины = провал уровня для обоих.
- **Две ракетки на одном поле** — оба игрока управляют своей ракеткой снизу
  (или одна снизу, другая сверху), общий пул жизней.
- **Ракетки напротив** — классический пинг-понг-вариант: ракетки на
  противоположных сторонах поля.

**Онлайн:**

- Приглашение других игроков в кооп (ссылка/код комнаты) — на базе Supabase
  Realtime (позиции ракеток, события ударов; синхронизация с приоритетом хоста).
- Комнаты на 2–4 игроков, статусы «в лобби / в игре», реконнект.
- Очные режимы: локальный кооп на одном экране (клавиатура/тач-зоны) как
  первый шаг до онлайн-синхронизации.

_Статус (решение от 24.09.2026):_

- **Локальный кооп «две ракетки на одном поле»** (общий пул жизней, одна снизу +
  одна сверху) — кандидат на следующий большой этап **после этапа A карт**.
  Объём средне-крупный: вторая ракетка в `paddleControl`/`inputHost` (тач-зоны
  и раздельные клавиши), HUD на двоих, правила проигрыша; физика/рендер уже
  разделены фасадами — главный риск не в них.
- **Разделённое поле** и **ракетки напротив** — не делать: обе схемы требуют
  переделки правил уровня и победы, а ценность для казуальной аудитории ниже.
- **Онлайн на Supabase Realtime — не делать в обозримом горизонте:** в проекте
  пока нет ни одного realtime-канала (только REST `scores`), а host-authoritative
  синхронизация + комнаты + реконнект — самый дорогой и рискованный пункт
  роадмапа. Пересмотреть, если локальный кооп покажет вовлечённость.

## Приоритеты (уточнены 24.09.2026 после анализа §13–§14)

1. **Боссы + механика ракетки + энергетические блоки** — ядро геймплея,
   наибольший рост вовлечённости (реализовано).
2. **Новые типы блоков (раздел 6)** — дешёвый контент поверх готовой физики
   блоков (реализовано).
3. **Перки и кампания** — roguelike-структура поверх ядра (реализовано).
4. **Система жизней + валюта + метрики** — экономика и обратная связь
   (реализовано).
5. **Карты игроков, этап A: локальные «коды карт»** (раздел 13) — ядро
   стабильно, формат опирается на готовый `buildFromSpec`; следующий этап.
6. **Локальный кооп «две ракетки на одном поле»** (раздел 14) — после этапа A
   карт; онлайн-кооп — вне текущего горизонта.
7. **Каталог карт + модерация (этап B, §13)** — после плейтеста этапа A.
8. Остальное — по мере готовности.
