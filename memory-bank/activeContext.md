## Последнее обновление (06.10.2026, решение по старту редактора карт)

- Согласована гибридная модель режимов: бесконечный режим использует seed-
  декорирование; кампания и будущие пользовательские режимы используют
  параметрические блоки из authoring spec.
- В `/docs/ROADMAP.md` актуализированы требования: параметрические блоки и группы,
  типизированные ссылки block/group, расширяемая матрица эффектов/анимаций,
  цвет по текущему HP 1–8, эллипс как первая форма с архитектурой для последующих
  форм, несколько условий победы, проверка проходимости, численная оценка
  сложности и простой/продвинутый режимы параметров.
- Уточнено правило победы: без босса/минибоссов уничтожаются все разрушаемые
  блоки; при наличии босса/минибоссов уничтожаются все соответствующие цели.
  После боевой цели шары останавливаются, игрок должен поймать падающий бонус,
  затем показывается завершение. Сложность имеет две компоненты (прочность/
  параметры и ожидаемое время), итог утверждает только модерация.
- Начальные условия победы будут авторским выбором из трёх режимов: все
  разрушаемые блоки, все боссовые цели, выбранные блоки/группы. После любой
  боевой цели обязательна остановка шаров и ловля падающего бонуса.
- В обычном режиме блок только в одной группе, группы не вкладываются; циклические
  ссылки запрещаются. Карта с ошибками не публикуется, но может сохраняться локально
  как черновик с понятными предупреждениями. Публикация проходит модерацию с
  проверкой игры/проходимости, сложности и авторским комментарием модератору.
- Перевод кампании на параметрические блоки отложен до появления редактора,
  накопления библиотеки карт и проверки градации сложности; старые `LevelSpec`
  пока не меняются.
- Параметры игры можно хранить в Supabase отдельной конфигурационной таблицей,
  но запись должна идти через отдельную защищённую Edge Function под
  `service_role`; прямой `insert/update` для `anon` запрещён. Локальные debug-
  overrides остаются отдельным механизмом. Направление независимое от редактора;
  нужны админ-аутентификация, опубликованные версии и безопасный fallback.
- Supabase также планируется для версионированных карт и пользовательского
  прогресса. Профили и прогресс должны быть привязаны к `user_id`, а не к нику;
  ник остаётся только отображаемым именем. Текущий режим по никам временный.
  Провайдерный слой авторизации должен допускать OAuth/OIDC-провайдера, доступного
  в России (кандидаты: Yandex ID, VK ID). Админская баланс-панель требует отдельной
  серверно проверяемой роли и не может опираться на `DEBUG_TOOLS`.
- В roadmap добавлен инвентарь реализованных эффектов (ARMOR, BRITTLE, PHASE,
  MAGNET, PULSE, SPRING, COTTON, SPIN, DRIFT, PORTAL, BOMB, SPLITS), кандидаты
  матрицы. Движение завершения карты уточнено: после цели остановить шары,
  ожидать ловли бонуса. Модерация и каталог теперь после локального редактора и
  тест-прогона; черновики локальные, на сервер отправляется только валидная заявка.
- В `docs/BLOCK_EFFECT_MATRIX.md` пользователь заменил все `?` матрицы конкретными
  значениями `да/нет/условно`. Обновлён статус: сами сочетания теперь заполнены,
  остались условные правила, спецификация бомбы, учёт SPLITS при победе, состав
  групповых эффектов MVP, режимы параметров, телеграфы/звук и числовые диапазоны.
  Обнаружена несимметричная пара «Вращение + Бомба» (нет/да), вынесена на решение;
  до подтверждения безопасное значение — запрет. Разделы открытых решений
  синхронизированы с заполненной матрицей.
- Следующий шаг: пользователь подтверждает перечисленные открытые решения и
  числовые диапазоны; затем контракт A1, валидатор, тест-прогон и UI.
